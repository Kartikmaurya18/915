# Market Data — web app

React + Vite + TypeScript single-page app for the Market-Data backend. Paper trading only.

## Develop

```bash
# terminal 1 — backend with real auth and mock data (see docs/OPERATIONS.md for the full list)
export AUTH_MODE=required JWT_SECRET=<32+ chars> MARKET_DATA_PROVIDER=mock
python -m alembic upgrade head
python -m uvicorn src.api.server:app --port 8000

# terminal 2 — the app on :5173, proxying /api and /ws to the backend
cd web && npm ci && npm run dev
```

With `AUTH_MODE=disabled` (the local default) the app skips sign-in and acts as a single local admin.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server with the API/WebSocket proxy (`BACKEND_URL` overrides `http://localhost:8000`) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Unit and component tests (vitest + jsdom) |
| `npm run build` | Type-check, then build to `web/dist` |
| `E2E_BASE_URL=http://127.0.0.1:8010 npm run test:e2e` | Browser code paths against a running backend started with `AUTH_MODE=required` |

## Production

FastAPI serves `web/dist` itself (`src/api/spa.py`): the shell with a Content-Security-Policy at `/` and
every client-side route, hashed bundles from `/assets` with a one-year immutable cache. `FRONTEND=legacy`
switches back to the original UI in `public/` without a rebuild. The Dockerfile builds the app in a Node
stage and copies `web/dist` into the Python image.

## Layout

```
src/
  api/          http.ts (fetch wrapper, single-flight refresh), types.ts, useConfig, usePaperState
  auth/         AuthContext.tsx (in-memory access token, refresh cookie, mode detection)
  realtime/     patch.ts, protocol.ts, client.ts (framework-free), RealtimeProvider.tsx (hooks)
  components/   Layout, guards, CandleChart, StatusPill
  pages/        AuthPage, Overview, Trading, Rrg, Quality, Logs, Settings
tests/          unit + component tests; fixtures/ holds patches generated by the real Python diff()
tests/e2e/      live tests (opt-in)
```

`tests/fixtures/patch_cases.json` is generated by `python web/tests/fixtures/gen_patch_fixtures.py`; regenerate
it whenever `src/realtime/patch.py` changes, so the TypeScript applier stays pinned to the server.
